# opencode 前端架构总结

本文梳理 `opencode web` 对应的前端代码结构。这里的前端主要指 `packages/app`，它是 opencode Web UI 和桌面端 UI 共同复用的核心应用代码。

## 1. 前端整体定位

`packages/app` 是一个 Solid + Vite 应用，构建后生成静态资源。`opencode web` 启动 `packages/opencode` 里的本地 server 后，会由 server 托管这些静态资源，同时提供 opencode API。

整体关系：

```text
opencode web
  -> packages/opencode 启动本地 HTTP server
  -> server 先处理 API 路由
  -> server 最后兜底返回 packages/app 构建出的前端页面
  -> 前端页面再调用同一个 server 的 API
```

桌面端也复用 `packages/app` 的主体 UI，但入口不同：

```text
Web 版:
packages/app/src/entry.tsx
  -> AppBaseProviders
  -> AppInterface

桌面版:
packages/desktop/src/renderer/index.tsx
  -> import @opencode-ai/app
  -> AppBaseProviders
  -> AppInterface
```

## 2. 启动入口

### `packages/app/src/entry.tsx`

浏览器端入口，类似普通前端项目里的 `main.tsx`。

主要职责：

- 读取当前运行环境，推导默认 server 地址。
- Web 环境下封装 `Platform` 能力，比如通知、打开链接、浏览器前进后退、刷新。
- 从 URL 查询参数里解析 `auth_token`。
- 创建初始 `ServerConnection.Http`。
- 调用 Solid 的 `render()` 把应用挂载到 `#root`。

关键流程：

```text
entry.tsx
  -> 创建 platform
  -> 创建 server connection
  -> PlatformProvider
  -> AppBaseProviders
  -> AppInterface
```

## 3. App 总壳和路由

### `packages/app/src/app.tsx`

这是前端应用的总壳，负责把全局 Provider 和路由组装起来。

主要职责：

- 注册基础 Provider：主题、语言、错误边界、QueryClient、Dialog、Markdown/File 渲染等。
- 注册业务 Provider：Settings、Permission、Layout、Notification、Models、Command、Highlights。
- 管理 server 连接和健康检查。
- 注入 `GlobalSDKProvider` 和 `GlobalSyncProvider`。
- 定义前端路由。

核心路由：

```tsx
<Route path="/" component={HomeRoute} />
<Route path="/:dir" component={DirectoryLayout}>
  <Route path="/" component={SessionIndexRoute} />
  <Route path="/session/:id?" component={SessionRoute} />
</Route>
```

路由含义：

```text
/                         首页
/:dir                     某个项目目录，dir 是 base64 编码后的路径
/:dir/session             项目下的新会话页
/:dir/session/:id         项目下的指定会话页
```

## 4. 页面结构

`packages/app/src/pages` 是页面层，主要分为首页、项目布局、会话页和全局布局。

### `pages/home.tsx`

首页。

主要职责：

- 展示 Logo。
- 展示当前 server 名称和健康状态。
- 展示最近项目。
- 打开项目目录。
- 跳转到 `/:dir`。

关键函数：

```ts
function openProject(directory: string) {
  layout.projects.open(directory)
  server.projects.touch(directory)
  navigate(`/${base64Encode(directory)}`)
}
```

它不直接处理 session，而是负责选择项目并进入项目工作区。

### `pages/directory-layout.tsx`

项目目录路由的中间层。

主要职责：

- 从 URL 里的 `:dir` 解码真实目录。
- 如果目录编码无效，弹 toast 并跳回首页。
- 为子页面注入项目级上下文：

```tsx
<SDKProvider directory={() => resolved}>
  <SyncProvider>
    <DirectoryDataProvider directory={resolved}>
      {props.children}
    </DirectoryDataProvider>
  </SyncProvider>
</SDKProvider>
```

可以理解为：进入某个项目后，所有项目级 SDK、同步数据和本地状态都从这里开始建立。

### `pages/layout.tsx`

全局主布局和侧边栏。

主要职责：

- 渲染标题栏 `Titlebar`。
- 渲染桌面端和移动端侧边栏。
- 管理项目列表、workspace 列表、session 列表。
- 处理项目拖拽排序、workspace 拖拽排序。
- 处理打开项目、关闭项目、重命名项目、创建 workspace。
- 处理全局事件通知，比如 permission/question toast、桌面通知、更新提示。
- 维护 sidebar 宽度、hover peek、移动端侧栏等 UI 状态。

它是整个应用外层 UI 的协调器。`home.tsx` 和 `session.tsx` 都渲染在它的 `<main>` 里。

### `pages/session.tsx`

会话主页面，也是前端业务最复杂的页面。

主要职责：

- 展示会话消息时间线。
- 展示新会话界面。
- 管理输入区 composer。
- 处理消息历史分页加载。
- 处理滚动、自动滚到底、hash 定位消息。
- 管理 diff/review 面板。
- 管理文件 tab。
- 管理 terminal 面板。
- 管理 follow-up queue。
- 支持 revert / restore。
- 通过 `sdk.client.session.*` 调用后端 session API。

最终页面结构大致是：

```text
SessionHeader
  -> 会话顶部栏

MessageTimeline / NewSessionView
  -> 消息时间线或新会话页

SessionComposerRegion
  -> 输入框、权限/问题/todo/followup/revert dock

SessionSidePanel
  -> 文件树或 review/diff 面板

TerminalPanel
  -> 终端面板
```

`session.tsx` 更像一个“页面协调器”，真正的 UI 和子逻辑被拆到了 `pages/session/*` 和 `components/session/*`。

### `pages/error.tsx`

错误页。

主要用于 `AppBaseProviders` 的 ErrorBoundary fallback，渲染运行时错误或初始化失败信息。

## 5. `pages/layout` 子目录

`packages/app/src/pages/layout` 是全局布局和侧边栏的辅助模块。

- `deep-links.ts`：处理 `opencode://` deep link，把外部链接转换成打开项目、打开新会话等动作。
- `helpers.ts`：布局和侧边栏使用的排序、显示名、错误消息、session 选择等工具函数。
- `inline-editor.tsx`：侧边栏项目名、workspace 名等内联编辑能力。
- `sidebar-shell.tsx`：侧边栏基础外壳。
- `sidebar-project.tsx`：项目级 sidebar item、项目拖拽 overlay 等。
- `sidebar-workspace.tsx`：workspace 级 sidebar item、workspace 拖拽 overlay 等。
- `sidebar-items.tsx`：session/workspace 列表项相关 UI。

## 6. `pages/session` 子目录

`packages/app/src/pages/session` 是会话页面拆出来的子模块。

- `message-timeline.tsx`：消息时间线渲染。
- `review-tab.tsx`：diff/review 内容面板。
- `session-side-panel.tsx`：右侧文件树/review 侧栏。
- `terminal-panel.tsx`：终端面板。
- `file-tabs.tsx`：文件 tab 区域。
- `helpers.ts`：session 页面通用工具，包括 tab、review 打开、尺寸调整等。
- `session-layout.ts`：从路由参数和布局状态中组织 session 页面需要的布局信息。
- `session-model-helpers.ts`：同步最近一次用户消息里的模型信息到本地偏好。
- `use-session-commands.tsx`：注册 session 页面快捷命令。
- `use-session-hash-scroll.ts`：根据 URL hash 定位消息。
- `file-tab-scroll.ts`：文件 tab 横向滚动辅助。
- `message-gesture.ts`：消息区手势处理。
- `message-id-from-hash.ts`：从 hash 中解析 message id。
- `handoff.ts`：session 切换时临时交接 tab 状态。

### `pages/session/composer`

输入区相关模块：

- `session-composer-state.ts`：输入区状态机。
- `session-composer-region.tsx`：输入区主 UI。
- `session-followup-dock.tsx`：follow-up 队列展示。
- `session-permission-dock.tsx`：权限请求展示。
- `session-question-dock.tsx`：问题请求展示。
- `session-revert-dock.tsx`：revert/restore 提示展示。
- `session-todo-dock.tsx`：todo 状态展示。
- `session-request-tree.ts`：请求树组织逻辑。

## 7. Server 连接层

### `context/server.tsx`

管理当前连接的 opencode server。

主要职责：

- 维护 server 列表。
- 维护当前 active server。
- server 健康检查和轮询。
- 记录每个 server 下打开过的 project。
- 支持 web、desktop sidecar、ssh proxy 等连接类型。

关键类型：

```ts
ServerConnection.Http
ServerConnection.Sidecar
ServerConnection.Ssh
```

Web 版通常是 `Http`，桌面版通常是 `Sidecar`。

## 8. SDK 和同步层

### `context/global-sdk.tsx`

全局 SDK 网关。

主要职责：

- 根据当前 server 创建全局 SDK client。
- 建立全局 SSE event stream。
- 对事件做缓冲、合并、节流。
- 按 directory 分发事件。
- 暴露 `client`、`event`、`createClient`。

普通 API 走：

```ts
useGlobalSDK().client
```

实时事件走：

```ts
useGlobalSDK().event.start()
useGlobalSDK().event.listen(...)
```

### `context/sdk.tsx`

项目级 SDK。

`global-sdk.tsx` 是全局的，而 `sdk.tsx` 绑定具体目录。

主要职责：

- 从 `GlobalSDK` 派生带 `directory` 的 client。
- 把全局事件按当前目录过滤后重新发射。
- 暴露 `useSDK()` 给项目页面使用。

典型使用：

```ts
const sdk = useSDK()
sdk.directory
sdk.client.session.list()
sdk.event.on("message.part.updated", ...)
```

### `context/global-sync.tsx`

全局数据同步中心。

主要职责：

- bootstrap 全局配置、provider、path、project 列表。
- 管理每个目录的 child store。
- 根据全局 event stream 更新全局数据或目录数据。
- 管理 provider、project、session 列表、todo 等跨页面共享数据。
- 提供 `globalSync.child(directory)` 获取某个目录的同步 store。

可以理解为：它是前端的全局缓存和事件 reducer。

### `context/sync.tsx`

项目级同步层。

主要职责：

- 基于 `useSDK()` 和 `useGlobalSync()`，操作当前目录的数据。
- 拉取 session 列表、单个 session、消息历史、diff、todo。
- 维护消息分页游标。
- 维护 optimistic message。
- 管理 session 缓存淘汰。

典型使用：

```ts
const sync = useSync()
sync.data.session
sync.data.message[sessionID]
sync.session.sync(sessionID)
sync.session.history.loadMore(sessionID)
sync.session.diff(sessionID)
```

## 9. 其他重要 context

`packages/app/src/context` 里还有很多横向能力：

- `platform.tsx`：平台抽象。Web 版和桌面版的差异通过这里抹平，比如打开文件、通知、存储、更新、剪贴板图片等。
- `layout.tsx`：全局布局状态，比如侧边栏、文件树、session panel、项目列表、tab 等。
- `local.tsx`：项目内本地偏好状态。
- `settings.tsx`：设置项。
- `models.tsx`：模型/provider 选择相关状态。
- `permission.tsx`：权限请求、自动响应等逻辑。
- `prompt.tsx`：输入框 prompt 状态。
- `file.tsx`：文件内容、选区、打开文件等。
- `terminal.tsx`：终端实例、terminal websocket、终端标题等。
- `comments.tsx`：review/comment 相关状态。
- `command.tsx`：命令系统和快捷键。
- `notification.tsx`：通知状态。
- `language.tsx`：多语言。
- `highlights.tsx`：高亮展示。

这些 context 基本构成了前端的“业务服务层”。

## 10. 数据流总结

打开项目：

```text
home.tsx
  -> openProject(directory)
  -> navigate("/:dir")
  -> directory-layout.tsx 解码 dir
  -> SDKProvider(directory)
  -> SyncProvider
  -> session 页面读取 useSDK/useSync
```

普通请求：

```text
页面组件
  -> useSDK() 或 useGlobalSDK()
  -> sdk.client.*
  -> opencode server HTTP API
```

实时事件：

```text
opencode server SSE
  -> global-sdk.tsx event stream
  -> global-sync.tsx applyGlobalEvent/applyDirectoryEvent
  -> sync.tsx/current child store
  -> 页面响应式更新
```

会话页面：

```text
session.tsx
  -> useSessionLayout 读取路由和布局信息
  -> useSync 读取 session/message/diff/todo
  -> MessageTimeline 渲染消息
  -> SessionComposerRegion 发送输入
  -> SessionSidePanel 渲染 file tree/review
  -> TerminalPanel 渲染终端
```

## 11. 阅读建议

如果目的是理解前端整体架构，建议按这个顺序看：

```text
1. packages/app/src/entry.tsx
2. packages/app/src/app.tsx
3. packages/app/src/context/server.tsx
4. packages/app/src/context/global-sdk.tsx
5. packages/app/src/context/global-sync.tsx
6. packages/app/src/pages/directory-layout.tsx
7. packages/app/src/context/sdk.tsx
8. packages/app/src/context/sync.tsx
9. packages/app/src/pages/home.tsx
10. packages/app/src/pages/layout.tsx
11. packages/app/src/pages/session.tsx
```

如果目的是自己写一套 Web UI，最关键的是先理解：

```text
server.tsx       当前连接哪个 opencode server
global-sdk.tsx   如何创建 client 和订阅全局事件
sdk.tsx          如何绑定项目目录
sync.tsx         如何拉取和缓存 session/message/diff/todo
```

如果只是改现有 UI，优先从：

```text
pages/home.tsx
pages/layout.tsx
pages/session.tsx
pages/session/*
components/session/*
components/prompt-input/*
```

开始会更直接。
